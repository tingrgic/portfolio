# Repository guidance

## Purpose and invariant
This is Tin Grgić's personal portfolio: a first-person premium black notebook on a restrained desk. Preserve the tactile notebook concept. Never flatten it into a generic portfolio hero/cards layout.

## Current renderer
The user explicitly requested a real 3D notebook after identifying CSS cover intersections. `src/scene/NotebookScene.ts` now owns rounded cover, page-block and curved-sheet geometry in Three.js. This supersedes the former CSS-strip/photographed-cover animation mechanism. Preserve all first-person, mobile framing, content continuity, keyboard and reduced-motion invariants below. The static photograph is a hardware-failure fallback only. Do not revert the main experience to a photograph with CSS masks.
Page snapshots use `capturePage.ts` (direct canvas painting with explicitly loaded fonts and decoded images), not SVG foreignObject, which dropped images in the supplied Safari recording. `warpPage.ts` aligns mesh ink with the readable affine HTML plane; retain both sides of that mapping to prevent text jumping at landing. The moving sheet must clear the raised ink meshes, not just the paper block.

## Visual and scrapbook rules
Latest clarification: phones show a single readable page, with the left leaf continuing naturally beyond the LEFT VIEWPORT EDGE. Do not clip the material at the centered notebook container, which creates an artificial cut edge inside the screen. Keep `.book-material { overflow: visible }` on mobile; the viewport clips the offscreen leaf. The fallback mobile frame height/width remains 1.72. The WebGL notebook has fixed world dimensions, with camera framing fitted to available width and small-viewport height; neither dimensions nor framing may depend on content. Intro/contact overflow remains reachable inside the page; work pages contain only the essential project image, name, one-line summary and link and must not scroll. The sole header logo is the bold lowercase `t` in `public/logo.svg`, with matching favicon and Apple touch icon.
Latest reference: aged lined journal on warm wood, with an editorial print treatment on the animated hands. Notebook geometry is fixed in `src/scene/NotebookScene.ts`; stage and fallback proportions are defined in `src/materials.css`, never by content length. Keep dimensions identical across sections at a given viewport; overflowing content scrolls within the paper area and remains keyboard accessible. Do not resize the object to fit text.
Warm paper, charcoal cover, locally hosted editorial serif headings and clean sans body copy. Caveat is limited to small personal notes. Preserve the photoreal notebook material, authentic project screenshots, gutter, page thickness and generous whitespace. Work uses linked taped printouts, rough marker backing and photocopy grain; labels and links stay readable. No emojis, random props, glass panels or rainbow accents.

## Motion
A brief seated first-person lean-in projects desk, notebook, tabs and hands through one Three.js perspective camera, then settles into a fixed reading angle. Never animate the camera independently from its desk plane. Forward turns use the right hand on the right page; backward turns use the left hand on the left page, per the latest user revision. Both pivot at the gutter, including the cropped mobile spread. Hand poses and page flex share a 10 fps clock; page flex uses an arc-length-preserving mesh sampled along 48 segments, with tangents constrained above the resting pages. Six poses per direction come from separately authored right/left atlases; never mirror them. Hand grip anchors use notebook-local physical coordinates. Preserve the old stationary page until the turning sheet covers it. Hold the opening until images/fonts are ready, keep Skip opening available, and make live content inert during turns. Preserve outgoing content on the moving leaf and place destination content underneath before the leaf lifts, so text is never floating over blank paper or popping in after landing. Support horizontal swipes as an optional alternative to buttons; preserve vertical scrolling and suppress accidental link taps after swipes. No orbiting camera or perpetual floating. Respect OS reduced motion and manual toggle; content must not depend on animation. Kill GSAP timelines on cleanup and prevent racing transitions.

## Accessibility and responsive layout
On phones, cap notebook width by available small-viewport height (`svh`) as well as width, reserving header/footer space so the complete object fits on first load with browser controls expanded. Preserve its aspect ratio and keep overflow inside the page. Header contains only the logo/wordmark.
Native links/buttons; semantic headings and landmarks; visible keyboard focus; at least 44px primary touch targets. Never require hover or swipe. Desktop spread and mobile single-page layouts are both products. Test 390×844, 430×932, 768×1024, 1366×768, 1440×900, 1920×1080, plus reduced motion and keyboard. Allow vertical scroll and text enlargement; avoid fixed-height clipped content.

## Hosting and performance
Default server binds 127.0.0.1. Opt-in :host scripts bind 0.0.0.0. No public deployment, tunnels, firewall changes or invasive network operations without explicit authorization. Port is CLI configurable. Keep assets local and optimized, Three.js is authorized for the physical notebook. Keep it dynamically loaded, cap pixel density, cache page textures and render only on changes. Do not add further heavy runtimes without material benefit. No analytics or remote fonts at runtime.

## Data integrity
Identity and role come from supplied config. Never invent email, project metrics, awards, authorship responsibilities, clients or outcomes. Empty email hides its link. Keep factual observations and asset provenance in docs/sources.md. Update projects in src/config.ts.

## Acceptance
Assert fixed notebook dimensions across intro/work/contact and enlarged copy at all six sizes. Check inner-page scrolling and scroll reset after navigation as well as ordinary document scrolling.
Build passes. Intro, both projects and contact work. Hand accompanies normal page turns. Keyboard and reduced motion work. No major console errors, overflow or tiny mobile copy. Required docs and local/VPN instructions remain accurate. Record real test results and limitations, not aspirational checkmarks.
