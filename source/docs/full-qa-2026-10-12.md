# Full portfolio QA — 2026-10-12

## Outcome

The supplied iPhone frames exposed two real bookmark defects: the tabs were visible through the closed front cover, and the later text treatment could appear offset within the projected 3D tabs.

Both defects are fixed. Bookmark meshes and accessible DOM controls share one cover-angle state and remain tucked until the cover clears them. Compact person, briefcase and envelope icons replace the variable-width words. Each icon is positioned at the projected mesh centre independently of its viewport-clamped 44px hit target. The reveal threshold was checked at 390×844 and 430×932; projected icon-to-tab centre error is at most 0.017 CSS px, including an artificial 180px clamp stress test.

No P0 defects remain in the automated and local visual scope described below.

### QA-03 — P1 — Asserted visual baselines

Current screenshots are review artifacts; most are not pixel assertions. Add `toHaveScreenshot()` baselines for reduced-motion settled pages, closed covers and the tab reveal boundary in one pinned container/OS. Keep geometry assertions as the primary cross-platform contract because GPU raster output varies. Official guidance: [Playwright visual comparisons](https://playwright.dev/docs/test-snapshots).

### QA-04 — P1 — Production performance budgets

Measure cold-cache LCP, INP, CLS, long tasks and opening/turn frame timings on a throttled mobile profile and a real iPhone. Target LCP ≤2.5 s, INP ≤200 ms and CLS ≤0.1. The dynamic scene chunk is the current optimization target; preserve dynamic loading, page-texture caching and the no-idle-render invariant. Guidance: [Core Web Vitals](https://web.dev/articles/vitals).

### QA-05 — P2 — WebGL context-loss and iOS memory/resume

Add an automated forced-context-loss/restore check, renderer resource counters across repeated routes, and a manual iOS background/resume loop. Continue disposing textures, materials, geometries and contexts. Guidance: [MDN WebGL best practices](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices) and [Three.js disposal](https://threejs.org/manual/pages/how-to-dispose-of-objects.html).

The full suite uses the Vite development server; the separate built-site smoke check covers four viewports. Add a dedicated production-preview Playwright project so critical journeys run against built assets on every release.

## Multi-agent / Hermes assessment

Three bounded parallel workstreams were used: mobile geometry, repository QA, and current workflow/browser research. Only the integrator edited shared source files.

Installing Hermes during this repair would not improve the product result. Its useful pattern is worktree isolation plus explicit task dependencies and verification. The current folder is not a Git checkout (`.git` is absent), so worktree isolation is unavailable here. If the project is placed in Git, use one worktree and branch per non-overlapping ticket, then merge serially through a single build/QA owner. References: [Hermes worktree guidance](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/git-worktrees.md) and [Playwright test agents](https://playwright.dev/docs/test-agents).
